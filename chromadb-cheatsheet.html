01

Connect

Pick a storage mode once. Every operation after this is the same API.

Start a client

SETUP

Python can be embedded or remote. TypeScript always talks to a running Chroma server.

Shell · install 
pip install chromadb
Python 
import chromadb

# 1. Local folder — no server needed
client = chromadb.PersistentClient(path="./chroma_db")

# 2. In-memory — great for tests
# client = chromadb.EphemeralClient()

# 3. Existing server — local or remote
# client = chromadb.HttpClient(host="localhost", port=8000)

# 4. Chroma Cloud
# client = chromadb.CloudClient(
#     api_key="ck-...",
#     tenant="your-tenant",
#     database="your-db",
# )

print(client.heartbeat())      # connection check
print(client.get_version())    # Chroma version
Shell · install + run server 
npm install chromadb
npx chroma run --path ./chroma_db
TypeScript 
import { ChromaClient, CloudClient } from "chromadb";

// Local server started above
const client = new ChromaClient(); // localhost:8000

// Remote or custom server
// const client = new ChromaClient({
//   host: "chroma.example.com",
//   port: 443,
//   ssl: true,
// });

// Chroma Cloud
// const cloud = new CloudClient({
//   apiKey: "ck-...",
//   tenant: "your-tenant",
//   database: "your-db",
// });

await client.heartbeat();
await client.version();
i Cloud shortcut: set CHROMA_API_KEY, CHROMA_TENANT, and CHROMA_DATABASE, then CloudClient() with no arguments can infer everything.

02

Collections

Collections are your tables: list them, open them, rename them, or drop them.

List + inspect

READ

List returns collection objects, oldest first. Count and metadata are right on the handle.

Python 
for col in client.list_collections():
    print(f"{col.name:28} {col.count():>6}  {col.metadata}")

# Page through many collections
# client.list_collections(limit=100, offset=0)
TypeScript 
const collections = await client.listCollections();

for (const col of collections) {
  console.log(col.name, await col.count(), col.metadata);
}

// Page through many collections
// await client.listCollections({ limit: 100, offset: 0 });

Get or create

CREATE

get_or_create is the daily default. Use create when an accidental overwrite would be a problem.

Python 
col = client.get_collection("docs")             # must exist
col = client.create_collection("docs")           # errors if it exists
col = client.get_or_create_collection("docs")    # safe everyday choice
TypeScript 
const col = await client.getCollection({ name: "docs" });
const created = await client.createCollection({ name: "docs" });
const safe = await client.getOrCreateCollection({ name: "docs" });
i If the collection already exists, get_or_create returns it and ignores the new metadata you passed.

Rename + edit collection metadata

WRITE

modify changes the collection itself — not the records inside it.

Python 
existing = dict(col.metadata or {})

col.modify(
    name="docs-v2",
    metadata={**existing, "owner": "team-ai"},
)
TypeScript 
await col.modify({
  name: "docs-v2",
  metadata: { ...col.metadata, owner: "team-ai" },
});
! Merge with the current metadata first if you need to preserve existing keys. Re-fetch the collection if you keep the old name as a variable.

Delete a collection

DANGER

Deletes the collection and every record, embedding, and metadata value in it. There is no undo.

Python 
client.delete_collection("docs")
TypeScript 
await client.deleteCollection({ name: "docs" });
NO-CODE PEEK
Browse a collection in your terminal

Arrow keys move, s searches, e edits the filter, Esc goes back.

chroma browse docs --path ./chroma_db
03

Records

Add, upsert, edit, and remove rows. If you remember one thing: prefer upsert for writes.

Choose the right mutation

CHEAT
add()New records onlyFastest insert. Duplicate-ID behavior has changed between versions, so don’t rely on it.
upsert()Create or updateBest default for imports, retries, and sync jobs.
update()Existing records onlyUse when the ID must already exist. Merge metadata yourself.
delete(ids=…)Remove exact rowsTargeted and easy to review.
delete(where=…)Remove by conditionBulk delete. Preview the filter with get() first.
modify()Collection settingsRename or change collection metadata — not record data.

Add records

CREATE

Every record needs a unique string ID. Documents are embedded automatically by the collection’s embedding function.

Python 
col.add(
    ids=["doc-1", "doc-2"],
    documents=[
        "Chroma stores vectors and metadata.",
        "Filters make retrieval predictable.",
    ],
    metadatas=[
        {"source": "handbook", "year": 2026, "status": "draft"},
        {"source": "blog", "year": 2025, "status": "live"},
    ],
)
TypeScript 
await col.add({
  ids: ["doc-1", "doc-2"],
  documents: [
    "Chroma stores vectors and metadata.",
    "Filters make retrieval predictable.",
  ],
  metadatas: [
    { source: "handbook", year: 2026, status: "draft" },
    { source: "blog", year: 2025, status: "live" },
  ],
});
! All supplied arrays are columnar: ids[0], documents[0], and metadatas[0] belong to the same record.

Upsert (safe write)

WRITE

Creates missing IDs and updates existing ones. Ideal for imports, retries, and “write this no matter what” jobs.

Python 
col.upsert(
    ids=["doc-1"],
    documents=["Revised text about embeddings."],
    metadatas=[{"source": "handbook", "status": "reviewed"}],
)
TypeScript 
await col.upsert({
  ids: ["doc-1"],
  documents: ["Revised text about embeddings."],
  metadatas: [{ source: "handbook", status: "reviewed" }],
});

Edit one record

WRITE

Read first, merge only the keys you want to change, then write back. This keeps the rest of the metadata intact.

Python 
rec = col.get(ids=["doc-1"], include=["documents", "metadatas"])
meta = dict(rec["metadatas"][0] or {})

meta["status"] = "reviewed"
meta["reviewer"] = "sam"

col.update(ids=["doc-1"], metadatas=[meta])

# Change the text too (it will be re-embedded)
# col.update(ids=["doc-1"], documents=["New body text."])
TypeScript 
const rec = await col.get({
  ids: ["doc-1"],
  include: ["documents", "metadatas"],
});

const meta = {
  ...(rec.metadatas?.[0] ?? {}),
  status: "reviewed",
  reviewer: "sam",
};

await col.update({ ids: ["doc-1"], metadatas: [meta] });

// Change the text too (it will be re-embedded)
// await col.update({ ids: ["doc-1"], documents: ["New body text."] });

Delete records

DANGER

At least one of ids or where is required. Filter deletes can remove many rows at once.

Python 
col.delete(ids=["doc-1", "doc-2"])

# Preview first:
# col.get(where={"status": "archived"}, include=["documents"])
col.delete(where={"status": "archived"})
TypeScript 
await col.delete({ ids: ["doc-1", "doc-2"] });

// Preview first:
// await col.get({ where: { status: "archived" }, include: ["documents"] });
await col.delete({ where: { status: "archived" } });
i To empty an entire collection, deleting and recreating it is usually simpler than looping through every ID.

Inspect records without a vector search

READ

count and peek are the quickest sanity checks. get retrieves by ID or metadata filter, not by similarity.

Python 
col.count()       # total records
col.peek(5)       # first few records

col.get(ids=["doc-1", "doc-2"], include=["documents", "metadatas"])
col.get(where={"status": "draft"}, limit=20)
col.get(limit=100, offset=0)   # page through everything
TypeScript 
await col.count();       // total records
await col.peek(5);       // first few records

await col.get({ ids: ["doc-1", "doc-2"], include: ["documents", "metadatas"] });
await col.get({ where: { status: "draft" }, limit: 20 });
await col.get({ limit: 100, offset: 0 });   // page through everything
i Defaults: get returns documents and metadatas; query also returns distances. IDs are always returned. Ask for embeddings explicitly with include=["embeddings"].
04

Query & read

Use query for “find similar”, get for “find exact”. Filters work with both.

Semantic search

READ

Chroma embeds the query text, finds the nearest stored vectors, and returns them ranked by distance.

Python 
res = col.query(
    query_texts=["How does Chroma store vectors?"],
    n_results=5,
    include=["documents", "metadatas", "distances"],
)

for id_, doc, meta, dist in zip(
    res["ids"][0],
    res["documents"][0],
    res["metadatas"][0],
    res["distances"][0],
):
    print(f"{dist:.4f}  {id_}  {doc[:60]}  {meta}")
TypeScript 
const res = await col.query({
  queryTexts: ["How does Chroma store vectors?"],
  nResults: 5,
  include: ["documents", "metadatas", "distances"],
});

res.ids[0].forEach((id, i) => {
  console.log(
    res.distances[0][i],
    id,
    res.documents[0][i],
    res.metadatas[0][i],
  );
});
i Lower distance = closer. The scale depends on the collection’s distance metric. n_results defaults to 10.

Filtered search

READ

Search by meaning, then narrow by metadata facts and document text. All conditions are applied before ranking.

Python 
res = col.query(
    query_texts=["refund policy"],
    n_results=5,
    where={
        "$and": [
            {"year": {"$gte": 2024}},
            {"status": "live"},
        ]
    },
    where_document={"$contains": "30 days"},
)
TypeScript 
const res = await col.query({
  queryTexts: ["refund policy"],
  nResults: 5,
  where: {
    $and: [
      { year: { $gte: 2024 } },
      { status: "live" },
    ],
  },
  whereDocument: { $contains: "30 days" },
});

Get by ID or filter

READ

No similarity ranking, no embedding cost. Great for exact lookups, exports, and checking a filter before deleting.

Python 
col.get(ids=["doc-1"])
col.get(where={"source": "handbook"}, limit=50)

# Include the stored vectors too
col.get(
    ids=["doc-1"],
    include=["documents", "metadatas", "embeddings"],
)
TypeScript 
await col.get({ ids: ["doc-1"] });
await col.get({ where: { source: "handbook" }, limit: 50 });

// Include the stored vectors too
await col.get({
  ids: ["doc-1"],
  include: ["documents", "metadatas", "embeddings"],
});

Result shape

CHEAT

query is grouped per input query. get is one flat list. Both are column-major.

Python 
# query → first query's batch
res["ids"][0]
res["documents"][0]
res["metadatas"][0]
res["distances"][0]

# get → flat columns
res["ids"]
res["documents"]
res["metadatas"]
TypeScript 
// query → first query's batch
res.ids[0]
res.documents[0]
res.metadatas[0]
res.distances[0]

// get → flat columns
res.ids
res.documents
res.metadatas
05

Filters

The JSON shape is the same in Python and TypeScript. Metadata filters use where; text filters use where_document.

Metadata operators

WHERE
NeedFilterNotes
Equals{"status": "live"}Shorthand for {"$eq": "live"}.
Not equal{"status": {"$ne": "draft"}}Use for exact exclusion.
Compare{"year": {"$gte": 2024}}Also $gt, $lt, $lte.
In a list{"status": {"$in": ["live", "review"]}}Scalar values only.
Not in a list{"status": {"$nin": ["draft", "archived"]}}Also matches records missing the key.
Array contains{"tags": {"$contains": "rag"}}Array elements must all be the same type.
Array excludes{"tags": {"$not_contains": "draft"}}Useful for tag lists.
AND / OR{"$and": [{...}, {...}]}Use $or for either condition. Nest as needed.

Metadata values: string, integer, float, boolean, or an array of one of those types. No None and no nested arrays.

Document filters

TEXT

Filter on the stored document text itself. Full-text matching is case-sensitive.

NeedFilter
Contains{"$contains": "refund"}
Not contains{"$not_contains": "draft"}
Regex match{"$regex": "^Return"}
Regex excludes{"$not_regex": "^Draft"}
AND / OR{"$and": [{...}, {...}]}

Pass this object as where_document in Python or whereDocument in TypeScript.

Compose conditions

PATTERN

Keep each field in its own object, then combine with $and or $or. This works for both metadata and documents.

JSON · shape 
{
  "$and": [
    { "status": { "$in": ["live", "review"] } },
    { "year": { "$gte": 2024 } },
    { "tags": { "$contains": "rag" } }
  ]
}
i Preview before you delete: run the same where with get() and inspect the IDs first.

Filters in context

EXAMPLE
Python 
col.get(
    where={
        "$and": [
            {"status": {"$in": ["live", "review"]}},
            {"year": {"$gte": 2024}},
        ]
    },
    where_document={"$contains": "retention"},
    limit=25,
)
TypeScript 
await col.get({
  where: {
    $and: [
      { status: { $in: ["live", "review"] } },
      { year: { $gte: 2024 } },
    ],
  },
  whereDocument: { $contains: "retention" },
  limit: 25,
});
06

Config & embeddings

Set distance and embedding behavior when the collection is created. These choices stick with it.

Distance metric

CREATE

Choose the space intentionally: l2 is the default, cosine is common for text, and ip is inner product.

Python 
col = client.create_collection(
    name="docs",
    configuration={"hnsw": {"space": "cosine"}},
)
TypeScript 
const col = await client.createCollection({
  name: "docs",
  configuration: { hnsw: { space: "cosine" } },
});

Bring your own vectors

CREATE

Turn off automatic embedding with embedding_function=None, then supply vectors yourself. Dimensions must match on every write and query.

Python 
col = client.create_collection("docs", embedding_function=None)

col.add(
    ids=["doc-1"],
    embeddings=[[0.12, -0.04, 0.88]],
    documents=["Optional source text"],
)
TypeScript 
const col = await client.createCollection({
  name: "docs",
  embeddingFunction: null,
});

await col.add({
  ids: ["doc-1"],
  embeddings: [[0.12, -0.04, 0.88]],
  documents: ["Optional source text"],
});

Use a hosted embedding model

OPTIONAL

The default embedding function runs locally and downloads a model on first use. Swap in OpenAI or another provider when you want managed embeddings. Keep the same embedding function when reopening a collection.

Python 
from chromadb.utils.embedding_functions import OpenAIEmbeddingFunction

ef = OpenAIEmbeddingFunction(model_name="text-embedding-3-small")

col = client.get_or_create_collection(
    name="docs",
    embedding_function=ef,
)
TypeScript 
import { OpenAIEmbeddingFunction } from "@chroma-core/openai";

const ef = new OpenAIEmbeddingFunction({
  modelName: "text-embedding-3-small",
});

const col = await client.getOrCreateCollection({
  name: "docs",
  embeddingFunction: ef,
});
i Set OPENAI_API_KEY in the environment. TypeScript needs the @chroma-core/openai package installed with npm install @chroma-core/openai.
07

Recipes

Small, reusable patterns for the things that come up every week.

Export a collection

READ

Dumps IDs, documents, and metadata to JSON. Add embeddings to include if you need the raw vectors.

Python 
import json

data = col.get(include=["documents", "metadatas"])

with open("docs-export.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2, ensure_ascii=False)
TypeScript 
import { writeFile } from "node:fs/promises";

const data = await col.get({
  include: ["documents", "metadatas"],
});

await writeFile("docs-export.json", JSON.stringify(data, null, 2));
! For a large collection, export in pages with limit and offset instead of one huge get.

Copy a collection

WRITE

Clone in batches. Passing stored embeddings preserves the original vectors instead of re-embedding.

Python 
src = client.get_collection("docs")
dst = client.get_or_create_collection("docs-copy")
data = src.get(include=["documents", "metadatas", "embeddings"])

size = 500
for i in range(0, len(data["ids"]), size):
    s = slice(i, i + size)
    dst.upsert(
        ids=data["ids"][s],
        documents=data["documents"][s],
        metadatas=data["metadatas"][s],
        embeddings=data["embeddings"][s],
    )
TypeScript 
const src = await client.getCollection({ name: "docs" });
const dst = await client.getOrCreateCollection({ name: "docs-copy" });
const data = await src.get({
  include: ["documents", "metadatas", "embeddings"],
});

const size = 500;
for (let i = 0; i < data.ids.length; i += size) {
  await dst.upsert({
    ids: data.ids.slice(i, i + size),
    documents: data.documents?.slice(i, i + size),
    metadatas: data.metadatas?.slice(i, i + size),
    embeddings: data.embeddings?.slice(i, i + size),
  });
}

Bulk upsert in chunks

WRITE

Keep batches modest — about 500 is a safe default. Larger batches can hit server payload limits.

Python 
rows = [
    {"id": "doc-1", "text": "First document", "meta": {"source": "faq"}},
    {"id": "doc-2", "text": "Second document", "meta": {"source": "faq"}},
]

size = 500
for i in range(0, len(rows), size):
    batch = rows[i:i + size]
    col.upsert(
        ids=[r["id"] for r in batch],
        documents=[r["text"] for r in batch],
        metadatas=[r["meta"] for r in batch],
    )
TypeScript 
const rows = [
  { id: "doc-1", text: "First document", meta: { source: "faq" } },
  { id: "doc-2", text: "Second document", meta: { source: "faq" } },
];

const size = 500;
for (let i = 0; i < rows.length; i += size) {
  const batch = rows.slice(i, i + size);
  await col.upsert({
    ids: batch.map((r) => r.id),
    documents: batch.map((r) => r.text),
    metadatas: batch.map((r) => r.meta),
  });
}
08

CLI & upkeep

Run the server, browse without writing code, back up the folder, and clean up the store.

Browse collections

VIEW

Point at a data folder and the CLI starts a temporary local server for the terminal UI. Already running? Use --local.

Shell 
chroma browse docs --path ./chroma_db

# server already running on localhost:8000
chroma browse docs --local
↑ ↓ move rows
↵ expand cell
s search / filter
e edit filter
space toggle operator
Esc back / exit

Run + maintain

SHELL

Use one process per data folder. Stop the server before copying or deleting the directory.

Shell 
# start a persistent local server
chroma run --path ./chroma_db

# optional: run inside Docker
docker run -v ./chroma-data:/data -p 8000:8000 chromadb/chroma

# reclaim space after big deletes (blocks reads/writes)
chroma utils vacuum --path ./chroma_db
! Vacuum is not routine maintenance. It locks the database while running. Stop the server first whenever possible.

Back up the local store

OPS

With the server stopped, a filesystem copy is the whole backup. Restore by pointing the client at the copied folder.

PowerShell 
Copy-Item -Recurse .\chroma_db .\chroma_db_backup
macOS / Linux 
cp -r ./chroma_db ./chroma_db_backup

Reset everything

DANGER

This wipes every collection in the current database. A server may also require allow_reset: true in its config.

Python · dev only 
client.reset()   # deletes all collections and records
TypeScript · dev only 
await client.reset();   // deletes all collections and records
! To wipe a local folder instead, stop Chroma first, then delete the data directory. Never delete it while the server is writing.
REST Raw HTTP quick reference +

Use this when you need curl or another language. Paths are relative to http://localhost:8000/api/v2; the default tenant and database are default_tenant and default_database. Collection endpoints take the collection UUID, not its name.

ActionMethod + path
HeartbeatGET /heartbeat
List collectionsGET /tenants/{tenant}/databases/{db}/collections
Create collectionPOST /tenants/{tenant}/databases/{db}/collections
Get / rename / delete collectionGET | PUT | DELETE …/collections/{collection_id}
Count recordsGET …/collections/{id}/count
Get / query / addPOST …/collections/{id}/get | query | add
Update / upsert / deletePOST …/collections/{id}/update | upsert | delete
Shell · curl 
BASE=http://localhost:8000/api/v2
TENANT=default_tenant
DB=default_database

# 1. Find the collection UUID
curl -s "$BASE/tenants/$TENANT/databases/$DB/collections"

# 2. Read records by collection UUID
curl -s -X POST \
  "$BASE/tenants/$TENANT/databases/$DB/collections/$COL_ID/get" \
  -H "Content-Type: application/json" \
  -d '{"limit": 10, "include": ["documents", "metadatas"]}'
! Raw REST does not generate embeddings from documents. Send vectors in embeddings for add, update, upsert, and query — or use a client, which handles embedding for you.
09

Gotchas

The small details that save an afternoon.

IDs are strings, unique per collectionUse stable IDs from your source system so upserts are predictable.
Write arrays are columnarThe same index in ids, documents, metadatas, and embeddings is one record.
Changing a document re-embeds itIf you don’t pass embeddings, Chroma recomputes them with the collection’s embedding function.
Metadata-only edits are cheapUpdating metadata does not trigger re-embedding.
get is not similarity searchUse query for nearest neighbors. get only retrieves by IDs and filters.
Full-text search is case-sensitive$contains and $regex do not automatically ignore case.
Filters are strict about shapeWrap multiple conditions in $and or $or; don’t put several fields in one filter object.
Preview bulk deletesRun the same where through get() and review the returned IDs before deleting.
TypeScript needs a serverPython can embed Chroma in-process. JS/TS connects over HTTP to a server or Chroma Cloud.
Collection metadata is not record metadatacol.metadata describes the collection; each record has its own metadata map.
! Two destructive calls to remember: collection.delete(where=…) removes matching records, and client.delete_collection() / client.reset() remove entire collections. Neither has an undo.
